# 两个 agent 同改一个项目 · 协作规矩（2026-10-21）

> 适用场景：同一个仓库、同一台机器上，有两个（或更多）Qoder 会话 / 模型在先后或同时改这个插件。
> 下面每条规矩都对应本项目**真实发生过**的一次事故或一次险情，不是假想的最佳实践。

---

## 1. 先分清楚：什么会被覆盖，什么不会

**提交不会互相覆盖。** Git 历史是只追加的：A 提交一个 commit、B 提交一个 commit，两个都留在
`git log` 里，谁也不会把谁冲掉。哪怕两个人改了同一个文件的相邻两行，只要各自提交过，内容都在。

**会被覆盖的是「还没提交的工作区内容」。** 因为两个会话现在**共用同一个检出目录**
（`D:\Git\ComfyUI_KeDou`），磁盘上只有一份文件。这时候不是"三方合并"，是**谁最后写文件谁赢**，
而且输的那一方不会收到任何报错。三种真实踩法：

| 踩法 | 后果 | 本项目实例 |
|---|---|---|
| 整文件写（Write 工具 / 编辑器保存 / `cp` 部署） | 对方刚写进去的改动静默消失 | 部署 `web/kedou_media.js` 时若手上是旧缓冲区，会连带抹掉并行会话的打包 UI |
| `git add -A` / `git commit -a` | 对方的半成品被装进**你的**提交信息里 | 2026-10-20 21:04 的看门狗改动，被别的会话 21:25–23:08 的 `feat(pack-ui)` 提交一起带走 |
| `git reset --hard` / `git checkout -- .` / `git stash` | 对方未提交的活直接没了 | 2026-09-29 词库改动全未提交，靠 `git stash push -u` 才保住 |

还有一次更隐蔽的：某次 `--amend` 把提交信息改成了 `fix(ui): 模型浮层列表改回不透明`，
但那次提交的**内容里根本没有 UI 改动** —— 信息与实际内容错位，事后只能 `git show --stat` 反查。
所以：**提交完自己验一遍信息配不配内容**，别靠记忆。

---

## 2. 硬规矩（默认：一次只有一个会话改插件）

1. **开工前先看现场**：`git status --short` + `git log --oneline -5`。
   工作区里出现不是你改的文件 → **停下来问用户**，不要"顺手一起提交"，也不要"先回滚干净"。
2. **只按路径暂存**：`git add web/kedou_media.js`。永远不用 `git add -A` / `git add .` / `git commit -a`。
3. **不跑破坏性命令**：`reset --hard`、`checkout -- <文件>`、`stash`、`clean -fd` 在共享工作区里
   等同于删对方的劳动。要保底就先 `git stash push -u` 并在回复里写清楚它还在。
4. **提交前自证**：`git show --stat HEAD` 的文件列表要和提交信息对得上；对不上就是混进了别人的改动。
5. **收尾即提交 + 即部署**：不留未提交改动"等下次再说"。未提交的时间越长，撞车概率越高，
   而且换模型/换会话时对方看不到你的进度。

---

## 3. 编辑层面的防覆盖

- **改之前必须刚读过这个文件。** Edit 工具在检测到文件被外部改动后会拒绝写入并要求重读
  （2026-10-20 在 `kedou_bridge/nodes.py` 上真触发过一次）。这个保护别绕：重读、看清对方改成什么样，
  再把你要的那一处叠上去。
- **整文件写是覆盖，不是合并。** `Write` / `cp` 部署前，先确认你手上那份是**当前**内容
  （刚从 HEAD 或刚验证过的工作区来的），不要从会话早期的缓冲区里倒出来。
- **部署目录是第二份拷贝**（`D:\ComfyUI_KeDou_v1\ComfyUI\custom_nodes\ComfyUI_KeDou`）。
  拷完必须 `cmp` 两边确认一致；不一致时先搞清是谁新谁旧，别硬盖。
- **热点文件按文件切开，别按行分工。** `web/kedou_media.js` 已经 150KB，图片加载器面板和打包面板
  同住一个文件，是最容易撞的地方。真要并行，把打包拆成 `web/kedou_pack.js` 比事后合并省事得多。

---

## 4. 确实要并行：各用各的 worktree

```bash
git worktree add ../kedou-pack -b pack-ui     # B 会话在这个目录、这个分支上改
# ...各自改、各自提交...
git merge pack-ui                              # 回到主检出合并
```

这样两边写的是不同磁盘路径，**不可能互相抹掉**；分歧会在 `merge` 时明明白白列成冲突让你解，
而不是静默丢一份。代价是要处理一次合并，收益是"丢改动"这一类事故从可能变成不可能。

## 6. 一句话版本

提交不会互相覆盖；**未提交的工作区会**。所以：开工先看现场、只按路径暂存、改前重读、收尾即提交。
