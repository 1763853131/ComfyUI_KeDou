## 二、图片加载器

### 阶段 1：初始形态（2026-09-22 至 09-23）

- `KedouImageLoader`（蝌蚪图片加载器）在基线里已经存在。
- 前端 `web/kedou_media.js` 渲染缩略图网格；选图状态写进隐藏控件 `media_state`。
- 一张图一路 IMAGE 输出，最多 10 路；支持多选、上传、从媒体库选图。

### 阶段 2：9/28 凌晨的四次迭代

同一天凌晨留下四份后端备份，能对应出实际改动顺序：

1. `__init__.py.bak-20260928-0247`：校验降级前的版本。
2. `__init__.py.bak-20260928-0552`：打包校验改成 `(errs, warns)` 双轨，缺输入降级为提醒。
3. `__init__.py.bak-20260928-0619`：新增批次模式。
   - `media_state` 增加 `batch` / `cursor`；批次开启时只把当前游标那一张送到「图片1」，前端循环改游标重排队，显存恒定。
   - 游标进入 `IS_CHANGED` 签名，避免文件没变时命中缓存不重跑。
4. `__init__.py.bak-20260928-0718`：槽位语义定型。
   - 启用槽 = 面板上的实际图片数，多余槽输出 `None`。
   - 废弃「复用最后一张填满」：旧逻辑会让下游收到多份相同参考图，权重翻倍、效果跑偏。
   - 个别图片失效只空对应槽，不前移错位；全部失效才报错。
- 同日后端另有提交 `f6aed98`：`media_state` 校验部分失效放行。

### 阶段 5：悬浮显示原图尺寸（2026-11-11）

- 提交 `ebb4496`；出包前的路径清理 `979738e`，tag `v1.0.5` 打在后者。
- 需求：在图片加载器的预览图上悬浮时显示图片尺寸。做成「悬浮放大层下方一条尺寸信息」，不新增按钮或浮层。
- 后端新增 `/ps/imgsize`（`kedou_bridge/media.py::image_size`）：`PIL.Image.open` 只读文件头拿宽高，不解码整图；按「路径 + mtime_ns + 字节数」缓存，上限 512 条；读 EXIF Orientation（274），5/6/7/8 交换宽高，与缩略图的 `exif_transpose`、节点 `_load_image` 口径一致。
  - `type` 指的目录里没有就自动试另一个，并回报命中的 `tab`（批次跑图时同名文件可能只落在 output）。
  - 不是图片 / 读不出 / 越界一律 404，前端不编数字。`/ps/version` 的 `features` 加 `image_size`。
- 前端悬浮层（`web/kedou_media.js`）：
  - `.kd-zoomcap` 显示 `宽 × 高`；开着对齐分辨率且尺寸有变化时追加 `→ 输出 宽 × 高`。
  - 前端复算桶尺寸 `kdBucketSize`，取整用 `kdRound`（半数取偶）复刻 Python `round()`，与 `nodes.py::bucket_size` 全表一致；直接用 `Math.round` 会在 1089×4096@1024 这档算成 544×1952（正确是 512×2016）。
  - 尺寸请求按「tab|sub/name」去重并缓存（上限 800 条，失败 10 秒内不重试），一次悬浮只发一次；`mousemove` 不重建 DOM。
  - 悬浮层定位改用实测 `offsetWidth/offsetHeight`（原来写死 344），加了尺寸条后高度会变，右下角不再越界。
  - 选择模式下不出放大图，只用 `.kd-chip` 小浮标显示尺寸；框选拖动时（`kdMarquee`）收起悬浮层。
  - 大图预览 `.kd-bigdim` 直接用 `img.naturalWidth/naturalHeight`，不额外发请求；媒体库格子复用同一套 `attachZoom`。
- 验证：`tests/test_image_size.py` 16 项（格式、子目录、EXIF 1/3/5/6/8、与缩略图比例一致、output 兜底、越界、缓存只读一次、覆盖后失效、缓存上限、桶不动点）；`tests/serve_image_size.py` + `tests/image_size_browser.js` 起隔离 aiohttp 真路由 + 无头浏览器 30 项断言，改动前备份跑同一套断言 17 项逐条失败。

### 阶段 6：悬浮提示合并文件名与尺寸（2026-11-11，v1.0.6）

- 起因：用户截图里浏览器原生的文件名提示（格子上的 `title`）正好压在悬浮尺寸条上，两块信息互相盖；且白主题下尺寸条整条看不见。
- 合并：悬浮层信息条 `.kd-zoomcap` 改两行 —— `.kd-zname`（文件名，超长省略，上限 322px）+ `.kd-zdim`（原图尺寸 + 对齐输出尺寸）。格子的 `cell.title` 去掉、改 `aria-label`，原生提示不再出现；文件名只剩悬浮层这一处可看，所以尺寸读不到时只收尺寸行、名字照常显示。
- 配色根因：新版前端 `main-*.css` 里 `--comfy-menu-bg:var(--background)`，白主题运行时注入白底 —— 旧注释「恒定深色」已过期。悬浮层是「深底 + 写死浅字」，不能再拿它当底色：`.kd-zoom` 底色写死 `#1c1c22`，两种主题一致（与格子角标 `.kd-no` 同口径）。拿 `--comfy-menu-bg` 当底色的 `.kd-card` / `.kd-libwin` 同时用 `--fg-color` 当字色，不受影响。仓库内两处过时的主题变量注释一并更新。
- 验证：浏览器断言扩到 43 项，白、黑两种主题各跑一遍全过（测试页按实测映射注入 `--comfy-menu-bg:var(--background)` 等变量，不注入就永远测不出白主题坑）；反向拿 v1.0.5 备份跑同一套，10 项逐条失败（合并信息、去 title、aria-label、深底、长名省略），33 项旧行为仍过；Python 全套 50 项 OK。
- 长文件名用例是真 fixture（约 480px 宽的中文名），不是前端假造：名字行 `scrollWidth > clientWidth` 且整层宽度不超上限才算过。

### 阶段 7：选择模式悬浮也显示预览图（2026-11-11，v1.0.7）

- 起因：用户要求选择模式悬停也出预览图。v1.0.5 当初为「点击留给选中」把选择模式的悬浮压成不含图的小浮标，属于过度保守 —— 悬浮层 `pointer-events:none`，本来就不挡点击。
- 改法：`renderPanel` 不再按 `selMode` 区分 url，两种模式都挂 512 缩略图 + 信息条；删掉 `.kd-chip` 特例 CSS 和 class 切换（`kdZoomShow` 保留「没有 url 时只留信息条」的兜底）。
- 点击归属不变：选择模式点击仍由 `kdGesture` 接管（选中 / Shift 范围 / 框选 / 点空白清空），格子不挂 `openBig` 的 onclick；框选期间 `kdMarquee` 收起悬浮层。
- 验证：浏览器断言 47 项，白 / 黑主题各跑一遍全过；反向拿 v1.0.6 备份跑同一套 3 项逐条失败（出预览图、图跟当前格子换、不再小浮标），44 项旧行为仍过；Python 全套 50 项 OK。
- 反向用例故意悬第二张 `rot.jpg`：悬浮层是单例，选择模式若不更新 `src` 会停在上一张的宽图上，这条断言能抓住「图没跟着换」的假通过。
