# ComfyUI_KeDou · 蝌蚪桥接

把 ComfyUI 里的工作流变成可点击的 **App**。

ComfyUI 本身没有"列出我的工作流和它们的参数"这样的接口，外部面板（启动器、Photoshop 面板等）拿不到数据。本插件补上这一层桥接：**列出应用 → 读取参数 → 持久化面板值（sidecar）→ 转成可直接提交的 API 格式 → 一键把工作流打包成应用包**。

> 除 ComfyUI 自带的 Pillow / numpy / aiohttp / PyYAML 外不额外安装任何依赖，一个文件夹即装即用。

---

## 安装

1. 把整个 `ComfyUI_KeDou/` 文件夹放进 `<ComfyUI>/custom_nodes/`
2. 重启 ComfyUI

```
custom_nodes/ComfyUI_KeDou/
├── __init__.py              # 入口：加载内部包、注册路由/钩子、导出节点
├── kedou_bridge/            # 后端实现（按职责拆分）
│   ├── paths.py             # 根目录 / 用户目录 / 工作流目录 / 越界检查
│   ├── common.py            # 应用解析共用常量与纯函数
│   ├── registry.py          # object_info、控件声明顺序与控件规格
│   ├── state.py             # sidecar 状态 + 写接口令牌/来源鉴权
│   ├── apps.py              # 应用发现、规格、回写、UI→API、执行图
│   ├── pack.py              # 打包候选、kapp 校验/落盘、编辑回写
│   ├── media.py             # 媒体清单、媒体选取、真缩略图
│   ├── nodes.py             # 两个自定义节点 + 空槽连线清理
│   └── routes.py            # /ps/* HTTP 路由注册
├── ui_to_api.py             # 界面格式 → API 格式转换
├── prompt_vault/            # vendored 提示词库实现
├── web/                     # 节点前端扩展（加载器 / 提示词框 / 打包面板）
├── locales/zh/main.json     # 中文文案
├── pyproject.toml           # 节点元数据（Comfy Registry / Manager）
└── LICENSE
```

> 拆分后入口文件只负责「加载 + 接线」；旧代码里的 `kedou.list_apps` 这类名字仍可用，
> 会动态转发到对应模块，不会拿到启动时的旧快照。

## 它提供什么

### 一、本地 HTTP 路由（挂在 ComfyUI 自己的端口上，默认 8188）

| 路由 | 方法 | 用途 |
|---|---|---|
| `/ps/version` | GET | 协议握手：`schema_version` + 本版能力（sidecar / 转换缓存 / 写令牌） |
| `/ps/apps` | GET | 列出全部「应用」：`{id, name, desc, param_count, has_image_input, node_count, format}` |
| `/ps/apps/{app_id}` | GET | 取单个应用定义：参数列表 + 输出节点；参数默认值已叠加 sidecar 保存值 |
| `/ps/apps/{app_id}/values` | POST | 把面板上的编辑存到 sidecar 状态文件（**不改工作流文件**） |
| `/ps/apps/{app_id}/graph` | POST | 界面格式 → **API 格式**，返回可直接 `POST /prompt` 的图；转换结果按文件版本缓存 |
| `/ps/media` | GET | 列媒体文件：`?type=image\|video\|audio&tab=all\|input\|output&q=关键词` |
| `/ps/thumb` | GET | 真缩略图：`?filename=&subfolder=&type=&w=256&fit=3x4`，按源图指纹落盘缓存；不透明出 JPEG、带透明出 PNG（**不能用 webp —— PS 面板的 `<img>` 走 Adobe 解码器，解不出来就是一片空白**）；`fit=<宽x高>` 把整图缩进这个比例再按 `#1a1a1a` 补边（**不裁边**，缩略图要让人认出画面；UXP 的 `max-*` 不锁宽高比，所以位图比例必须严格等于面板格子）；ComfyUI 自带的 `/view?preview=` 只重编码不缩尺寸，一屏原图必卡 |
| `/ps/pack/candidates` | GET | 打包前：列出工作流里**可暴露成参数的控件候选** |
| `/ps/pack` | POST | 按已有工作流文件生成 `<stem>.kapp.json` 应用包 |
| `/ps/pack/apps` | GET | 列出可编辑的 `.kapp.json` 应用包（打包面板「编辑已打包的应用」用） |
| `/ps/apps/{app_id}/package` | GET | 取原始 kapp 包（`graph` + `params` + `outputs`），供打包面板回填编辑 |
| `/ps/pack/save` | POST | 打包面板专用：前端已构好 API 图，这里只校验 + 落盘；带 `target` 时回写同一个 `.kapp.json` |
| `/ps/pack/app` | POST | 按 **ComfyUI 官方 App Mode 格式**写 `<stem>.app.json`（UI 图 + `extra.linearMode` / `extra.linearData`）；带 `target` 时回写同一个官方包 |
| `/ps/pack/linear` | POST | 按 **官方 App Builder 的勾选结果**（`extra.linearData`）直接生成 `.kapp.json`，不需要二次勾选；带 `target` 时回写同一个包（面板暂无入口，接口保留） |
| `/ps/prompts` | GET | **语库**清单（只含主动保存的 `.md`，不含历史），连**实际读取的目录和它的来源**一起返回：`?use=文生图&q=关键词` |
| `/ps/prompts/save` \| `delete` \| `use` | POST | 存语库条目 / 删除（进 `.trash`）/ 计次 |
| `/ps/prompts/history` | GET / POST | 自动历史：GET 列表（`?use=&q=`），POST 记录（hash 去重、50 条封顶） |
| `/ps/prompts/history/delete` \| `history/clear` | POST | 删一条 / 清空历史 |
| `/ps/prompts/phrases` | GET | **词库**清单（短词/标签，带分组、分类、收藏、计次） |
| `/ps/prompts/phrases/save` \| `delete` \| `use` | POST | 新建/编辑词、删除、计次 |
| `/ps/prompts/categories` | GET / POST | 语库/词库的自建分类：`?scope=prompts\|phrases` 取列表；POST `{scope,name,group?}` 新建 |
| `/ps/prompts/vault` | POST | 改词库目录（写 `user/default/kedou_prompt_vault.txt`）；传空串回默认 |

### 二、自定义节点

| 节点 | 显示名 | 说明 |
|---|---|---|
| `KedouImageLoader` | 蝌蚪图片加载器 | 直接在节点上选图（缩略图网格，由 `web/kedou_media.js` 渲染），输出一批图像。 |
| `KedouPromptBox` | 蝌蚪提示词输入框 | 提示词输入 + 按用途过滤的语库/词库/历史（`web/promptlib.js`），直通输出 prompt。 |

图片加载器底栏（节点底部 KeDou 那一行）有 **「长边缩放」** 下拉：
选 1024 / 1280 / 1536 / 2048 / 2560 / 3072 / 4096 时，每张输出图按长边缩到该尺寸以内，
宽度等比跟着变；只缩不放，比上限小的图保持原样。选「原尺寸」= 不限制。
该值存在节点的 `media_state` 里，会随工作流保存；普通输出和批次模式都生效，
改了之后 `IS_CHANGED` 会变，不会拿旧缓存凑合。旧数据里不在预设中的值会临时列进下拉，不会被改掉。

输出点位（IMAGE 槽）按**实际会出图的张数**给出，并**始终多留一个空位**（没到 50 路上限时）：
只放 1 张图也有「图片1 / 图片2」两个点位，连上第一个就能立刻往下接第二个，不用先补图。
批次模式固定 1 路（+1 空位），选择模式的张数 = 选中张数（+1 空位）；
已连线的槽一律保留（临时删图不断线），空槽的连线在后端 `/prompt` 入口被剔掉，
所以接到 Batch Images 这类下游不会因为 `None` 崩掉。

## 两种库 + 历史

节点上有三个按钮：**语库**（长提示词）、**词库**（短词/标签）、**历史**（自动记录）。
点哪个就打开哪个列表，面板内部不再分标签页，少一次点击；面板贴在提示词输入框正右方，
右边放不下会翻到左边，不会盖住输入框。节点下方的常用按钮只放置顶语库
（只显示缩名，最多 4 个字）；**词库和历史不进常用区**，避免短词和频繁变动的历史把这里挤满。

「保存」会先弹去处：**保存到语库**（写 `.md`）或 **保存到词库**（写 JSON，落在「我的词 · 未分类」）。

- **语库**：一条一个 `.md`，只有点「保存」/ 手动新建时才写文档；Obsidian 装不装都不影响读写。
  面板顶部可按「分类」筛选，编辑条目时也能改分类；选中的分类会作为新保存内容的默认分类。
- **词库**：短词放 `.kedou/phrases.json`，首次使用从 `prompt_vault/phrases_seed.json` 播种，
  按「大组 → 分类」浏览，支持收藏、搜索、新建/编辑/删除；新建/移入的词默认进
  「我的词 · 未分类」，并按更新时间排在前面。短词只有主动增改时才写盘。
- **历史**：放 `.kedou/history.json`，出图后自动记录，hash 去重、50 条封顶。
  每条只显示一行正文，鼠标悬停展开（最多 4 行，超出在正文里滚动）；右侧次数/日期为两行小字，
  今天/昨天带时间，更早只显示月-日，完整时间看悬停提示。
  近似提示词会自动折叠成「迭代卡」：主行显示最新版与「N版 · 总次数」，点 ▸ 展开旧版本；
  搜索时改为平铺显示每一条命中。
  历史**不会**生成 `.md`，也不会混进语库；旧版本留在 `00_History` 的历史笔记会在首次访问时
  迁进 JSON，原文件移入 `.trash`（可找回）。
- **图片排列**：词库面板里多一个同名分组，和短词共用搜索栏；点一条就加载到画布上的图片加载器，
  右键可重命名/删除。详见下文「图片排列（Sets）」。
- **新建分类**：语库和词库的搜索栏旁都有「新建分类」按钮；空分类也会保存在
  `.kedou/categories.json` 里，刷新或重启后不会消失。

右键还能跨库转换：

- 历史 → **添加到语库** / **添加到词库**（复制一份，历史保留）
- 词库 → **移动到语库**（先建长提示词，成功后再删短词）
- 语库 → **移动到词库**（先建短词，成功后再删 `.md`）

词库**逻辑**在 `prompt_vault/` 包里 —— 那是插件自带的一份 vendored 副本（上游是独立仓库，
改完用它的 `sync.py` 推过来），所以 clone 本插件即可用，不需要额外装什么。

库位置按这个顺序解析，谁装都先长在一个能用的地方，不写死任何人的盘符：

1. 环境变量 `KEDOU_PROMPT_VAULT`
2. `user/default/kedou_prompt_vault.txt` 首行 ← 库面板底部「改路径」写的就是它
3. ComfyUI 设置项 `Kedou.PromptVault`（手改 `user/default/comfy.settings.json`）
4. 默认 `user/default/kedou_prompts`（第一次建库会投放 3 条示例讲格式）

面板底部常驻显示当前实际在读的目录和来源，指错了能立刻看出来。
排查或改逻辑时看 `prompt_vault/`，接口是上面的 `/ps/prompts*`。

节点上的条目是「点一下插入、再点移除」：插到当前光标处，前后按已有标点自动补 `, `，
不会重复追加；已插入的条目会高亮。不需要先理解追加/替换之类的模式。

### 参考图写法（@ 图片）

参考生视频模型不会自己猜「第几张图是谁」，必须在提示词里点名。不同模型的点名格式不一样，
提示词框里有一行 **引用 / Reference** 下拉，**在用途选「图生视频」或「参考生视频」时出现**；
先选模型，再输入 `@` 或点 **@ 图片**，从画布上的「蝌蚪图片加载器」里选一张插入；
弹出的列表里每张图都带缩略图、输出槽号和文件名，不用靠文件名猜。
下拉项把模型名放在前面（`Seedance · @图片N`、`MiniMax H3 · <Picture N>`…），找起来更快。
**图片本身仍要接到模型**，这里只负责写对提示词。

| 写法 | 模型 / 入口 | 示例 |
|---|---|---|
| `@图片N` / `@Image N` | Seedance 2.x | `@图片1 的人物作为主体` |
| `<Picture N>` | MiniMax H3 | `<Subject 1> is the person in <Picture 1>` |
| `图 N` / `Image N` | 万相 Wan 2.7 | `图 1 在图 2 里玩耍` |
| `@图N` | Vidu Q2+（网页/Studio） | `@图3 骑着 @图1，在 @图2 上飞驰` |
| `<<<image_N>>>` | 可灵 3.0 Omni（API） | `一只<<<image_1>>>在月光下奔跑` |

补充：可灵网页端输入 `@` 调用的是元素名；H3 还有 `<Video N>`、`<Audio N>`、`<Subject N>`；
万相的中英文编号分别计数（`图 1` 与 `视频 1` 互不影响）；Veo 3.1 / Luma Ray3 不用编号 token，
Runway Gen-4 网页端用自己起的 `@名字`，所以这三种没放进下拉。

编号 = 图片加载器的**输出槽顺序**（选择模式下是选中顺序）。接线时按同样顺序把 IMAGE 接到模型；
画布上有多个图片加载器时，编号各自从 1 开始，菜单底部会再提醒一次。
切换写法会把已经写入的旧格式编号一并换成新格式，不用手动改。

提示词里出现能识别的引用编号时，输入框下方会显示对应图片的小缩略图（同一张图多处引用只占一格）。
点缩略图可定位到提示词里的那处编号；图片被删、换序或找不到时显示红色 `?`，悬停有说明。
图片加载器里删除/重排/改选中后，缩略图会通过 `kedou:media-changed` 事件自动刷新。

### 图片排列（Sets）

图片加载器顶部有个 **排列** 按钮：把当前的图片顺序、选择模式和批次模式存成一条记录，
下次打开同一个加载器（或新建一个）就能一键还原，不用再一张张翻回来。

- **只存文件名和顺序**，不复制图片、不占额外空间；图片需仍在 `input` 或 `output` 目录里
  （也就是「已导入」或媒体库里生成的图）。
- 可以给排列起名字，留空自动按时间命名（`排列 2026-10-19 20:30`）。
- 加载时逐张检查：能找到的按原顺序放回，找不到的会提示「缺少 N 张：…」，
  其余图片照常恢复，不会因为缺一张就整个失败。
- 选择模式和批次模式、以及选中的图片顺序也会一起还原（只保留仍存在的选中项）。
- 同名保存会覆盖，最多保留 100 个排列；删除是两段式：点 × 先变「确认」，2.5 秒内再点才真的删。

排列不是媒体侧的孤立数据：它和词库放在同一个库目录里（`<词库目录>/.kedou/image_sets.json`），
并作为 **词库面板里的「图片排列」分组** 出现，因此：

- 可以按名字或文件名搜索，行内直接看前 6 张缩略图和「N 张 · 批次 · 选择」状态；
- 点一条就加载到画布上的图片加载器（有多个加载器时会先问加载到哪个）；
- 右键可以 **重命名 / 删除**，和词条一样在这里统一管理；
- 改词库路径时排列会跟着走；旧版本 `user/default/kedou_image_sets.json` 会在首次读写时自动迁入。

后端接口：`GET /ps/image-sets`、`POST /ps/image-sets/save|load|rename|delete`
（实现在 `kedou_bridge/image_sets.py`）。

## 两种「应用」来源

插件同时识别两种工作流，**同名时 `.kapp.json` 优先**；官方格式也能由本插件生成（见下）。

|  | 官方应用模式 | 自研应用包 `.kapp.json` |
|---|---|---|
| **识别方式** | 文件名 `*.app.json`，或 `extra.linearMode == true` | `{"kedou_app": 1, ...}` |
| **参数定义** | `extra.linearData.inputs` 勾选（勾到哪个控件就叫什么名） | `params` 逐条声明 `node` + `input` + `widget` |
| **图格式** | 界面格式，每次运行都要做 UI→API 翻译 | **直接存 API 格式**，无翻译、无位置对位 |
| **参数** | `linearData` 勾选 | 显式声明 |
| **输出** | `extra.linearData.outputs` | 显式列出节点 id |
| **能否生成** | `POST /ps/pack/app`（用画布 UI 图） | `POST /ps/pack` / `/ps/pack/save` |

应用包长这样：

```json
{
  "kedou_app": 1,
  "name": "示例应用",
  "desc": "",
  "graph": { "3": { "class_type": "KSampler", "inputs": { } } },
  "params": [
    { "node": "6", "input": "text", "label": "提示词", "widget": "text", "default": "" }
  ],
  "outputs": ["9"]
}
```

> 设计取舍：官方应用模式有三笔"税"——参数靠勾选、`widgets_values` 按位置对位、每次运行都要翻译一遍。
> 应用包把这三样全部显式化，插件本身保持**纯通道**：声明是什么就是什么，不对任何具体应用做特判。

### 生成官方 `.app.json`

官方「应用」不是另一种文件，就是 UI 工作流本身多了两个字段（前端 1.55 的 App Mode）：

```json
{
  "id": "54bb395d-3e60-4c94-b525-85523901575b",
  "nodes": [ "…整张界面图，位置/连线/控件值原样…" ],
  "extra": {
    "linearMode": true,
    "linearData": {
      "inputs": [["54bb395d-3e60-4c94-b525-85523901575b:483:seed", "种子"]],
      "outputs": ["461"]
    }
  }
}
```

`POST /ps/pack/app` 收 `{name, workflow, params:[{node,input,label?}], outputs:[…], target?}`：

- `workflow` 必须是画布序列化的 **UI 图**（`app.graph.serialize()`）。官方应用保留整张界面图，
  API 图反推不回位置与连线，所以 **kapp 不能直接转成官方包**；反过来官方包随时可以打成 kapp。
- 每条参数按 `"<顶层id>:<节点id>:<控件名>"` 写进 `linearData.inputs`，三段都 `encodeURIComponent`；
  顶层 `id` 缺失时自动补一个 uuid（前端加载时会认回来）。
- 自绘节点写的是 DOM 把手：`media_state → kedou_media`、`prompt_state → kedou_promptbox`
  （与真机 App Builder 落到文件里的形态一致）。
- 校验不过不落盘：画布上不存在的控件、不存在的节点/输出节点都如实报错，绝不静默丢弃。
- 写出来的文件 ComfyUI 自己的 **Apps 侧栏**（按 `*.app.json` 后缀）也能直接打开；
  同名 `.app.json` 与 `.kapp.json` 并存时，本插件仍按 `.kapp.json` 优先。

打包面板里「输出格式」下拉即可切换：选「本插件应用包」走 `/ps/pack/save`（API 图），
选「官方应用」走 `/ps/pack/app`（画布 UI 图，格式固定、不能原地编辑已打包的 kapp）。

> 自带的自测：`tests/test_official_app.py`（生成 → 读回 → 与真机样例对照，不需要启动 ComfyUI）。

### 读官方 App Builder 的勾选结果（接口，面板无入口）

`POST /ps/pack/linear` 仍然保留：给它一张带官方构建器勾选（`extra.linearData`）的工作流，
就能直接产出 `<stem>.kapp.json` —— 哪些参数、什么顺序、什么显示名、什么描述都沿用构建器的，
`outputs` 用构建器勾的输出节点，图用同一张 UI 图转成 API 图。适合脚本或以后接到「保存后自动生成」。
面板上的「从 App Builder 导入」区块已按反馈移除（它只列内部控件名，反而是干扰）。

### 打包面板：点选 / 全部选项两个子标签

面板拆成两个子标签，**默认「点选」**：

- **点选**（默认）：在画布上点任意一个能暴露的参数就加进清单，再点一次移出。
  每个参数行的行首还有一个勾选框（照官方 App Builder 的样子）：点选开着时每行左边会让出
  24px，方框落在这条空白里，参数名整体右移，和官方构建器一致；勾上的行外面套一圈蓝框，
  鼠标停在任何一行上会先给它一圈虚框，方框和行的对应关系一眼能看清。
  方框的位置和命中都按节点卡片里的**行元素本身**算（`getBoundingClientRect`），所以缩放、
  换行、折叠高级输入、多行文本框都不会错行；折叠起来没画出来的行、被别的节点压住的行、
  画布外和被面板挡住的行都不画。切页或关面板立即清掉方框和那份缩进。
  被连线顶掉、只剩一个输入点的参数（比如提示词接到提示词框上）照样有方框：行首临时补上
  同样的缩进，圆点往右让开，方框落在它前面。纯连线的口（CLIP、模型、latent 这类）没有方框、
  点了也没反应，跟官方构建器一样——它们没法让用户在应用里填。
  鼠标停在方框上时提示里会写明「现在由连线提供」，提醒你这个参数眼下是由上游给的。
  清单里的顺序就是 kapp 里参数的顺序，可直接改名、改控件类型、上下调序、移出。
  点选只在「点选」页生效，切页或关面板立即摘掉监听；勾选时会拦掉紧随的
  mousedown / mouseup / click，不会顺手把参数带进输入状态。老渲染器（关掉 Vue 节点）
  没有行元素，退回控件自己的 `.y` 估算，方框画在节点左外侧。
- **全部选项**：原来的按节点分组勾选表原样保留，只是不再占默认页 —— 折叠节点、子图里的项、
  或者被别的节点挡住时，展开这一页手动勾最快。

编辑已打包的应用时，清单按包里原来的参数顺序填好（不是画布顺序），改完直接存回同一个文件。

### 清单排序、清空和「用户看到的样子」

- 清单里每条左边有个 `⋮⋮`，**按住上下拖**就能换位置（长清单一拖就到，比一下一下点箭头快）；
  上下小箭头也还在，两种都行。清单从上到下就是应用里的参数顺序。
- 清单底下「全部移出」一次清空清单，画布上什么都不动，参数一个不少。
- 再往下是「用户看到的样子」：按清单顺序把应用**照原样排一遍** —— 应用名、描述、
  每个参数的名字和控件（文本框 / 数字框 / 开关 / 下拉 / 上传框）都照类型画出来，
  末尾一个「运行」按钮示意一下。纯预览，点不动，也不会影响打包。展开/收起状态会记住。
- 一个参数都没勾的时候「生成应用包」是灰的、点不动，省得生成一个空应用。

### 应用名

面板打开时「应用名」默认就是**当前工作流的名字**（页签上显示的那个，去掉 `.json` / `.app.json` /
`.kapp.json` 后缀）；新建还没保存的工作流没有真名字，才退回 `untitled`。
名字没被手动改过之前会跟着工作流走 —— 面板开着换工作流，名字自动换成新的那个；
手动改过之后就不再多手，编辑已有应用时同样以包里的名字为准。

### 编辑已打包的应用

打包面板顶部的「编辑已打包的应用」下拉会列出工作流目录里所有 `.kapp.json`：

- 选中后，应用里的参数会映射回当前画布的候选行并自动勾选；当前工作流里已经不存在
  的参数会收进「当前工作流中不存在」分组，仍可改标签 / 控件类型或取消勾选。
- **默认只改参数声明，原 `graph` 和 `outputs` 原样保留**，不会因为当前画布不同而悄悄换掉应用跑的东西。
  需要换图时勾选「用当前工作流更新图」，这时才会重新抓 API 图并重算输出节点。
- 编辑时「应用名」只改包内的显示名，**文件名保持不变**；保存通过 `target` 回写同一个文件。
- 保留原图时，新勾选的参数必须真的存在于原图里（且不能是连线输入），否则前端直接提示，
  后端 `_kapp_validate` 仍会再兜一层。

### 控件识别

- 候选类型按 ComfyUI 真机的 `widget.type` 判定（`number` / `combo` / `toggle` /
  `text` / `customtext` / `slider` 等），不再只看 `INPUT_TYPES` 的大写声明；
  数值、布尔、下拉都能正确落到应用的数字框 / 开关 / 下拉。
- 每行标题取控件自己的本地化标题（如「宽高比」「百万像素」「倍数」），不再统一用节点标题；
  没有控件标题时才退回控件名。
- 按钮、预览、曲线、3D 编辑等不随工作流序列化的专用控件不会列为参数，避免把只读预览打包进去。
- 重新编辑旧应用时，旧的 `text` 类型和节点标题会按当前识别结果升级；用户自己改过的标题/类型保留。
- 读官方应用时，输入引用按规范形解析：控件名取自 `"<图id>:<节点id>:<控件名>"`，第二个元素只当**显示名**
  （旧式 `[节点 id, 控件名]` 仍兼容）。以前会把中文标签当成控件名，默认值和类型全丢。
- 控件值优先读 `widgets_values_named`（前端 1.55+ 才有，键就是控件名），不再受"按位置对位"错位影响；
  老工作流没有这个字段时仍按声明顺序取下标。
- 自绘节点的 DOM 把手（`kedou_media` / `kedou_promptbox`）读回时还原成数据控件
  （`media_state` / `prompt_state`），类型按图像输入 / 提示词处理，默认值取真实控件那份。

## 应用状态、缓存与写接口安全

**参数值不再写回工作流。** `/ps/apps/{id}/values` 保存在
`user/default/kedou_app_state/<相对路径hash>.json`（原子写入），工作流文件保持只读。
读取应用/构建执行图时会自动叠加这些值，请求里显式传的值优先级更高。
旧的 `.bak` 文件不再产生；已有 `.bak` 可以手动删除。

**UI→API 转换带缓存。** 转换结果按 `(文件 mtime, 文件大小, 节点注册表指纹)` 缓存，
运行期只做深拷贝 + 注值。工作流改动或节点增删后自动失效；每次返回里的 `cache`
字段是 `hit` / `miss` / `off`，便于排查。

**写接口默认拒绝外部网站来源。** 启动时会生成
`user/default/kedou_bridge_token.txt`。外部面板可以在 POST 请求里带
`X-Kedou-Token: <文件内容>`；本机无 Origin、`null`、loopback `http(s)`、
以及 `file://` / `plugin://` / `uxp://` / `app://` 这类本地面板来源仍可直接调用。
设置环境变量 `KEDOU_BRIDGE_REQUIRE_TOKEN=1` 后，所有写接口都必须带令牌。
如果面板发来的 Origin 不在上述范围，可用 `KEDOU_BRIDGE_ALLOWED_ORIGINS` 追加
（逗号分隔，例如 `plugin://com.adobe.photoshop`）。
如果 ComfyUI 暴露到局域网，建议同时开启严格模式，并只给可信面板分发令牌。
